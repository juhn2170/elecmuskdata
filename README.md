# elecmuskdata

전국 무인 교통단속 카메라 데이터를 매일 자동으로 받아 정리하고, SQLite 파일로 게시하는 저장소입니다.
ElecMusk 앱(개인용 Tesla 앱)의 과속 카메라 알림에 사용합니다.

## 데이터 출처 (필수 표시)

- **공공데이터포털(data.go.kr) 「전국무인교통단속카메라표준데이터」**
- 이용허락범위: **저작자표시**
- 구간단속: **공공데이터포털 「한국도로공사_구간단속현황」** (CSV, 이용허락범위 제한 없음)
- 도로(`roads-latest`): **© OpenStreetMap contributors**, [ODbL 1.0](https://opendatacommons.org/licenses/odbl/). `roads.db`는 OSM에서 만든 데이터베이스이므로 ODbL로 공개합니다. 원본: Geofabrik 한국 추출본.
- 이 저장소의 데이터는 원본을 정제·가공한 것이며, 원본과 다를 수 있습니다. 실제 단속 여부를 보장하지 않습니다.

## 받는 곳

Release [`cameras-latest`](../../releases/tag/cameras-latest)

| 파일 | 내용 |
|---|---|
| `cameras.db` | SQLite. `camera`(카메라), `section`(고속도로 구간단속, `method`=연결 방법), `meta`(버전, 출처, 기관별 기준일자) |
| `version.json` | 버전, 건수, 데이터 해시, DB의 SHA-256과 크기, 변경 건수. 앱은 이것만 먼저 확인 |
| `changes.json` | 지난 게시본 대비 추가·삭제·변경 건수 |
| `patch.json.gz` | 지난 게시본 → 이번 게시본 증분 (바뀐·추가된 행, 지운 키, 구간 전체, meta). `version.json`의 `patch.from`이 앱의 버전과 같을 때만 쓴다. 바뀐 행이 5,000개를 넘으면 만들지 않는다 |

Release [`roads-latest`](../../releases/tag/roads-latest) (매주 일요일)

| 파일 | 내용 |
|---|---|
| `roads2.db.gz` | SQLite (gzip), 형식 2. 카메라 길과 그 둘레 약 50~100m 길의 연결망. `edge(id, u, v, flags, lanes, geom)`: 교차점 u~v 사이 길 한 토막 (geom: Encoded Polyline 1e-5, 첫 점 절대값; flags: 0~3비트 등급, 4비트 u→v, 5비트 v→u 통행, 6비트 터널, 7비트 다리; lanes: OSM 차로 수, 없으면 0). `tile(t, edges)`: 0.005도 타일 → 간선 id (오름차순 차이값 varint). `approach(key, edges)`: 카메라 키 → 차가 달려 그 카메라에 닿는 방향 간선 (id×2+방향, varint). `meta`: 버전, OSM 기준 시각, 거리 예산 |
| `roads2.json` | 버전, 건수, 간선 수, 푼 파일의 SHA-256과 크기 |

## 동작

1. 매일 05:23(KST)에 GitHub Actions가 실행됩니다. 수동 실행도 가능합니다.
2. API에서 전체를 받습니다 (1,000건씩, 약 45회 호출).
3. 정제합니다: 코드 표기 통일(`01`→`1`), 범위 밖 좌표 제거, 설치장소의 "(A→B)" 방향 문구 추출, 자체 키 부여(관리번호 + 시도 + 좌표).
4. 한국도로공사 구간단속 CSV를 받아 `section`에 넣습니다. 이 데이터에는 좌표가 없어서, 표준데이터의 구간단속 카메라를 시점·종점 카메라로 연결합니다 (`method` 열에 방법 기록).
   - `km`: 같은 노선에서 설치장소에 적힌 이정(km)이 1km 이내이고 시점/종점과 방향이 맞는 카메라
   - `km+pair`: 한쪽만 이정으로 찾았으면, 반대쪽은 같은 노선의 시점↔종점 카메라 중 직선거리와 카메라의 구간 길이가 구간 길이와 맞는 것
   - `name`: 둘 다 이정으로 못 찾았으면, 설치장소·방향 문구에 시점·종점 시설물 이름(예: 덕평SA → 덕평)이 '시점→종점' 순서로 있고 직선거리가 맞는 쌍
   - 노선 옛 이름(대전당진, 상주영덕 → 당진영덕 등)은 현재 이름으로 맞추고, 설치장소의 '부산방향'처럼 반대 방향이 적힌 카메라는 뺍니다.
   - 연결 못 한 구간도 이정 정보와 함께 남깁니다. CSV를 못 받은 날은 지난 게시본의 구간을 그대로 씁니다.
   - 2026-11-21 데이터 기준 157구간 중 99구간 연결 (이전 방식 63구간).
5. 지난 게시본과 비교해서 바뀐 게 없으면 게시하지 않습니다.
6. 카메라 수가 지난번보다 20% 넘게 줄면 게시하지 않고 실패로 남깁니다.
7. 실행 결과를 `logs/runs.tsv`에 기록합니다 (365일 지난 기록은 자동 삭제).

### 도로 (roads.yml, 매주)

1. Geofabrik 한국 OSM(약 300MB)과 최신 `cameras.db`를 받습니다.
2. 차가 다니는 길만 읽어 교차점에서 자르고, 일방통행을 반영해 방향 있는 간선을 만듭니다. 회전 제한(좌회전 금지 등, via 가 교차점인 `restriction`)도 읽습니다.
3. 과속 카메라마다 25m 안의 길에 붙이고(가장 가까운 길보다 15m 안쪽이면 여럿), 거꾸로 차가 달려 그 지점에 닿는 간선을 모읍니다. 거리 예산은 고속도로 1200m, 일반 600m, 어린이보호 400m이고, 카메라 길보다 한 등급 아래 길까지만, 회전 제한으로 들어올 수 없는 길과 유턴은 빼고 따라갑니다.
4. 카메라 길 둘레 약 50~100m 안의 다른 길도 넣습니다 (앱이 "카메라 길과 다른 길 중 어디에 더 맞는가"로 판단).
5. 2026-11-21 기준 34,294건 중 32,979건이 길에 붙고, 간선 736,053개, `roads2.db`는 약 31.7MB (압축 17.9MB)입니다.

## 직접 돌려 보기

```
python -m unittest discover -s tests        # 서비스키 없이 테스트
DATA_GO_KR_SERVICE_KEY=... python scripts/fetch.py out/raw.json
python scripts/build.py out/raw.json prev out
```

Python 3.12 표준 라이브러리만 사용합니다. 서비스키는 GitHub Secrets `DATA_GO_KR_SERVICE_KEY`에만 둡니다.
